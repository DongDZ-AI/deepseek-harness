# Agent Note: Local Tesseract OCR tool

Status: implemented

English | [中文](2026-08-17-ocr-tool.zh.md)

## Problem

Model routes served by the shipped DeepSeek adapter declare `inputModalities: ['text']` for every catalog model (`packages/llm/llm-deepseek/src/adapter.ts`), so the multimodal `read_image` tool refuses any image on those routes with "model does not declare image input". Local work that starts from an image — a screenshot, a scan, a photo of a document — therefore had no path into the model context on the default deployment.

## Decision

**A new first-party consumer plugin `@deepseek-ai/dsh-tool-ocr` registers the `ocr_image` tool**, which runs a locally installed Tesseract binary on a resolved image file and returns the extracted text. The result is plain text, so the tool works on text-only model routes — the gap `read_image` cannot serve. The plugin lives at `packages/ocr/tool-ocr/` and follows the standard tool pattern: `name`/`inject`/`apply` entry, schemastery `Config` with defaults in `invariant.ts`, and a `defineTool` registration whose output schema is the lossless `{ text, language }` pair.

**The tool resolves its target through `ctx.fs`** — session cwd, `stat` existence and regular-file validation, and `fs/observed` emission — before handing `ctx.fs.processPath(target)` to the child process, so OCR reads keep the framework's filesystem discipline and audit trail.

**Execution is a cooperative child process.** `execFile` receives the configured `binPath`, the argv from `buildTesseractArgs`, a `timeout`, and `exec.signal`; the tool declares `timeoutMs` as its cooperative budget. Missing-binary (`ENOENT`), non-zero-exit, and stderr failures surface as structured messages that name the fix (install tesseract or set `binPath`). Output beyond `maxOutputChars` is truncated with an explicit notice.

## Alternatives considered

**Extend `read_image` to shell out to OCR when the route lacks image input.** Rejected because it couples a multimodal contract with a text-fallback strategy and would change a shipped tool's semantics; the seam is better served by a distinct text-returning tool.

**Resolve the path with `node:fs` directly and skip `ctx.fs`.** Rejected because it would bypass the filesystem policy, observation events, and session-cwd semantics that every model-facing filesystem tool shares.

**Import the session-cwd helper from `dsh-tool-fs` internals.** Rejected as a cross-package internal dependency; the few lines of cwd derivation are replicated locally with a comment.

## Consequences

Deployments that add `tool-ocr` to their composition gain `ocr_image` for any text-only model route; the default web and headless bundles do not mount it, so the change is opt-in. The tool depends on a platform binary and its language packs (`chi_sim` and friends), so recognition quality and availability vary by machine — a deployment concern expressed as `binPath`/`defaultLanguage` config rather than hardcoded. `buildTesseractArgs`/`validateLanguageCode`/`validatePsm`/`truncateOutput` are pure and unit-tested; the child-process boundary is mocked in tests, and a one-off real-binary run against a local screenshot confirmed end-to-end extraction in both `eng` and `chi_sim`.
