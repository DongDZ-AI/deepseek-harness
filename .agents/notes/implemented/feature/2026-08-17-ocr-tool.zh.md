# Agent Note: 本地 Tesseract OCR 工具

Status: implemented

[English](2026-08-17-ocr-tool.md) | 中文

## Problem

内置 DeepSeek 适配器为其目录中的每个模型声明 `inputModalities: ['text']`（`packages/llm/llm-deepseek/src/adapter.ts`），因此多模态 `read_image` 工具在这些路由上会以"model does not declare image input"拒绝任何图片。默认部署中，以图片为起点的本地工作——截图、扫描件、文档照片——便没有进入模型上下文的路径。

## Decision

**新增一等公民消费者插件 `@deepseek-ai/dsh-tool-ocr`，注册 `ocr_image` 工具**：对解析后的图片文件运行本地安装的 Tesseract 二进制，返回提取出的文本。结果纯文本，因此该工具可在仅文本的模型路由上工作——这正是 `read_image` 无法服务的空白。插件位于 `packages/ocr/tool-ocr/`，遵循标准工具模式：`name`/`inject`/`apply` 入口、schemastery `Config`（默认值在 `invariant.ts`）、以及输出 schema 为无损 `{ text, language }` 的 `defineTool` 注册。

**工具通过 `ctx.fs` 解析目标**——会话工作目录、`stat` 存在性与常规文件校验、`fs/observed` 事件——之后才把 `ctx.fs.processPath(target)` 交给子进程，使 OCR 读取保持框架的文件系统纪律与审计轨迹。

**执行是协作式子进程。** `execFile` 接收配置的 `binPath`、`buildTesseractArgs` 生成的参数、`timeout` 与 `exec.signal`；工具将 `timeoutMs` 声明为其协作预算。二进制缺失（`ENOENT`）、非零退出与 stderr 失败均以指明修复方式的结构化消息呈现（安装 tesseract 或设置 `binPath`）。超过 `maxOutputChars` 的输出会截断并附加明确提示。

## Alternatives considered

**扩展 `read_image`，在路由缺少图片输入时转而调用 OCR。** 拒绝：这会把多模态契约与文本回退策略耦合，并改变已发布工具的语义；该空白更适合由独立的文本返回工具来填补。

**直接用 `node:fs` 解析路径、跳过 `ctx.fs`。** 拒绝：会绕过所有模型面向文件系统工具共享的文件系统策略、观察事件与会话工作目录语义。

**从 `dsh-tool-fs` 内部导入会话工作目录辅助函数。** 拒绝：属于跨包内部依赖；工作目录推导的几行逻辑在本地复制并附注释。

## Consequences

在装配中加入 `tool-ocr` 的部署，其任何仅文本模型路由都会获得 `ocr_image`；默认 web 与 headless bundle 不挂载它，因此该变更按需启用。工具依赖平台二进制及其语言包（`chi_sim` 等），识别质量与可用性因机器而异——这是以 `binPath`/`defaultLanguage` 配置表达的部署关注点，而非硬编码。`buildTesseractArgs`/`validateLanguageCode`/`validatePsm`/`truncateOutput` 为纯函数并有单测覆盖；子进程边界在测试中以 mock 隔离，另以一次性真实二进制运行（对本地截图分别用 `eng` 与 `chi_sim`）确认了端到端提取。
